## 0. 先澄清一个事实

> **网页端并不需要外部服务器** —— ESP32 自己就能当 Web 服务器，把页面存在 flash 里直接发给浏览器。所以"没有服务器"不等于"不能做网页端"。
>
> **但我们仍然决定不做网页端。** 理由不是"不可能"，而是"**原生上位机更合适**"：
>
> | 原因 | 说明 |
> |---|---|
> | 离线 AI | App 可把模型打包进去，不依赖外网 |
> | 摄像头权限 | 原生可稳定访问，浏览器受 HTTPS / 混合内容限制 |
> | 蓝牙 / 串口 | 浏览器能力弱，原生直接可用 |
> | 代码复用 | 一套 .NET 代码同时覆盖电脑端与 App |
>
> **这是主动选择，不是被"没服务器"逼出来的。**

## 1. 产品定义

### 1.1 是什么

一只**掌心大小、能走能演，还能学你动作精华和表情**的开源机器人。

核心设计是**模块化运动平台**：同一个本体，换运动模块即可在四足 / 轮式 / 履带 / 双足之间切换。

### 1.2 给谁用

| 用户 | 场景 | 诉求 |
|---|---|---|
| 嵌入式爱好者 | 复刻一只小机器狗 | 便宜、好买、教程清楚 |
| 内容创作者 | 拍段舞让它跟着跳，录成短视频 | 好玩、出片 |
| 学生 / 毕设 | 步态控制或情感交互演示 | 可改、可扩展 |
| 二次开发者 | 接大模型做语音宠物 | 有开放协议 |

### 1.3 目标

| 层级 | 目标 |
|---|---|
| 硬件 | 物料 ≤ ¥151（B 档）；¥300 启动跑通 |
| 软件 | 上位机可完成控制、视频处理、图片处理、设置、仿真 |
| 商业 | 零库存、正现金流、按单生产 |

### 1.4 明确不做

不做网页端；不做机器人端视觉；不做通用物体识别；不做 12 自由度；不做量产开模；不做备货。

## 2. 系统架构

### 2.1 三个部分

```
┌──────────────────────────────────────────────────┐
│  上位机（软件）— 大脑                             │
│  电脑端 WPF · App MAUI                            │
│  视频处理 / 图片处理 / 基本设置 / 仿真 / 控制      │
└──────────────┬───────────────────────────────────┘
               │ 小文本指令（WiFi / 蓝牙 / 串口）
               │ 只发指令与参数，不发视频图片
┌──────────────▼───────────────────────────────────┐
│  机器人本体（嵌入式 + 硬件 + 设计）                │
│  ESP32 + PCA9685 + OLED + 运动模块                 │
│  执行动作 · 渲染表情 · 安全保护                    │
└──────────────────────────────────────────────────┘
```

### 2.2 职责分工（全项目基准）

| 能力 | 机器人本体 | 上位机 |
|---|---|---|
| 舵机实时控制 / 步态 / 表情 | ✅ | ❌ |
| 悬崖 · 堵转 · 低电保护 | ✅ | ❌ |
| 接收参数与指令（小文本） | ✅ | 发送 |
| 状态回传（电压 / 温度 / 姿态） | ✅ | 接收 |
| **处理视频**（视频 → 动作精华） | ❌ | ✅ |
| **处理图片**（表情 / 手势） | ❌ | ✅ |
| **基本设置**（参数配置） | 接收 | ✅ 界面 |
| 仿真 | ❌ | ✅ |
| 烧录 / 标定 / 批量测试 | 被操作 | ✅ |

**原则：需要毫秒级实时反馈的放机器人，需要算力的放上位机。**

### 2.3 关键约束：机器人只收"小文本"

| 数据类型 | 大小 | 发给机器人？ |
|---|---|---|
| 视频帧 | 几 MB/秒 | ❌ 永不 |
| 图片 | 几十 KB ~ MB | ❌ 永不 |
| 姿态关键点 | ~1 KB/帧 | ❌ 上位机内部消化 |
| 表情参数（12 维） | ~50 字节/帧 | ✅ |
| 动作包 `.motion` | 2–10 KB | ✅ |
| 状态回传 | ~100 字节 | ✅ |

**推论**：机器人不需要图像处理能力，这正是它能用几块钱芯片跑起来的原因。
**附带收益**：画面从未离开上位机，可把"画面不出设备"当卖点。

### 2.4 通信方式

| 通道 | 用在 | 阶段 |
|---|---|---|
| 串口（USB） | 烧录、出厂标定、配网、底层调试 | P0 起 |
| WiFi（TCP / WebSocket） | 日常控制、动作下发、状态回传 | P0 起 |
| 蓝牙（BLE） | App 配网、近距离控制 | P2 起 |

三种通道**共用同一套指令集**，由软件定义、嵌入式实现。

### 2.5 配网方案（取消网页端后必须重新设计）

| 阶段 | 方式 | 说明 |
|---|---|---|
| P0 | **编译时写死** WiFi 账号密码 | 只做几台样机，够用 |
| P1 | **上位机（PC）串口配网** | 交付创始团时工程师现场配 |
| P2 | 保留串口配网 | |
| V3 | **App 蓝牙配网** | 用户自助 |

> 取消网页端后，不能再走"连热点 + 浏览器打开页面"那套。**这是取消网页端最主要的连带改动。**

## 3. 机器人本体（嵌入式 + 硬件 + 设计）

### 3.1 硬件方案

| 部件 | 选型 | 成本 |
|---|---|---|
| 主控 | ESP32-C3 SuperMini | ¥13 |
| 舵机驱动 | PCA9685（16 路，余 8 路给扩展） | ¥10.5 |
| 舵机 | SG90 9g 180° ×8（+2 备用） | ¥55 |
| 显示 | 0.96" OLED（I2C） | ¥8.3 |
| 电源 | 5V/3A 有线或 2S 18650 + 降压 | ¥12 / ¥41 |
| 线材五金 | 杜邦线 + M2 螺丝 | ¥13 |
| 结构 | 3D 打印件（代打） | ¥50 |
| **B 档合计** | | **≈ ¥151** |

### 3.2 模块化运动平台

| 模块 | 执行器 | 成本 | 售价 |
|---|---|---|---|
| 四足（标配） | 8× SG90 180° | ≈ ¥60 | 含在整机 |
| 轮式 | 2× SG90 360° | ≈ ¥27 | ¥49 |
| 履带 | 2× SG90 360° | ≈ ¥40 | ¥69 |
| 双足 | 4× SG90 + 尾撑 | ≈ ¥45 | ¥99 |
| 桌宠底座 | 无 | ≈ ¥5 | ¥29 |

**技术要点**

- 运动模块**自带 PCA9685**，本体只提供 4pin（5V/GND/SDA/SCL）—— 与扩展口统一
- 模块用 **I2C 地址区分**（0x40 四足 / 0x41 轮式 / 0x42 履带 / 0x43 双足），上电自动识别
- 轮式与履带用 **360° 舵机**驱动（同价 ¥5.5，PWM 调速，不需要电机驱动板）

### 3.3 固件职责

| 模块 | 职责 |
|---|---|
| 动作解释器 | 解析 `.motion`，按时间轴驱动通道 |
| 舵机调度 | 限速、限流、限制同时动作数（保护电源） |
| 表情渲染 | 12 维参数 → 128×64 帧，含缓动 |
| 姿态管理 | 站立 / 趴下等状态切换与安全过渡 |
| **指令服务** | WiFi / 串口 / 蓝牙 接收小文本指令 |
| 状态回传 | 电压、温度、姿态、错误码 |
| 安全守护 | 悬崖检测、堵转超时、低电保护、看门狗 |

**技术栈**：ESP32 Arduino Core + Adafruit_PWMServoDriver + ESPAsyncWebServer（**仅做 TCP/WS 服务，不提供网页**）+ ArduinoJson + LittleFS + FreeRTOS。

### 3.4 明确不做（硬件硬约束）

| 不做 | 原因 |
|---|---|
| **机器人端视觉** | **ESP32-C3 没有摄像头接口（无 LCD_CAM），也不支持 PSRAM** |
| 通用物体识别 | ESP32 级别 MCU 做不到 |
| 本地 AI 推理 | 同上 |

**若要加摄像头**，必须换 **ESP32-S3 + PSRAM**（+¥20–30）或加视觉协处理器（+¥30–45）。**这会改变主控选型，必须在采购前定。**

**当前判断：P0/P1 不加摄像头。** 需要视觉的玩法全部走上位机摄像头（画质更好、零成本、角度灵活）。

**摄像头唯一值得加的理由**：玩法需要**低延迟**（追球、跟随人、实时避障——走一趟网络就追不上）。若只是想"识别这是什么物品"，上位机完胜。

## 4. 上位机（软件主线）

### 4.1 两个形态

| 形态 | 技术 | 阶段 | 用途 |
|---|---|---|---|
| **电脑端** | **WPF (.NET 8)** | **P0 起（主力）** | 调试、标定、烧录、批量测试、动作编排 |
| **App** | **.NET MAUI** | V3 起 | 用户日常控制、蓝牙配网、离线 AI |

> **P0/P1 只做电脑端。** App 等到"需要用户自助"和"需要离线 AI"时再做。

### 4.2 职责

| 职责 | 说明 |
|---|---|
| 控制机器人 | 发指令、播放动作、切表情、读状态 |
| **处理视频** | 视频 → 提取动作精华 → 生成 `.motion` |
| **处理图片** | 表情识别、手势识别（摄像头） |
| **基本设置** | 步态、表情、网络、安全阈值 |
| 仿真 | 步态设计与验证 |
| 生产工具 | 出厂标定、批量测试、固件烧录 |
| 通信 | WiFi / 蓝牙 / 串口 |

### 4.3 功能模块与工时

**电脑端（WPF）**

| 3 | **出厂标定**（P1 交付必需） | P0 | 5 天 |
| 4 | **动作编辑器**（时间轴、关键帧、预览） | P1 | 8 天 |

**App（MAUI，V3）**

| # | 模块 | 工时 |
|---|---|---|
| 1 | 连接与蓝牙配网 | 5 天 |

### 4.4 仿真

| 用途 | 工具 |
|---|---|
| **步态设计与防摔验证** | **MuJoCo（Python）** |
| 动作 3D 预览 | three.js（**仅作上位机内嵌组件，不是产品形态**） |

> **模型是现成的**：`lukehollis/sesame-ml` 提供 CAD 派生的 **MJCF** 与验证过的 **URDF**，含质量、惯量、执行器限位。**P0 的 3D 建模工作量 = 0。**

### 4.5 复用设计（为 App 铺路）

```
PalmRobot.Core  ← .NET 类库
  ├─ 通信协议（串口文本 + WiFi JSON + BLE）
  ├─ .motion 数据模型
  ├─ 标定算法
  └─ 校验逻辑
      ├── WPF 电脑端引用
      ├── MAUI App 引用      ← 未来不用重写
      └── CLI 工具引用
```

**这是为 MAUI 铺路的关键一步，写第一个上位机功能时就要建立。**

## 5. 设计（外壳）

### 5.1 原则：不要从零设计

**直接复用 sesame-robot 的 STL / CAD（Apache-2.0），只改外壳，不动腿部结构。**

| 改动范围 | 影响 |
|---|---|
| 只改头/身体外壳、屏幕窗口、配色 | 步态参数不用重调 |
| 改腿部结构 | 步态要重调（1–2 周工时） |

### 5.2 第一版最小改动清单

| # | 改动 | 目的 |
|---|---|---|
| 1 | 头部外壳（OLED 窗口约 27×27 mm） | 定义角色 |
| 2 | 身体外壳 | 同上 |
| 3 | 配色（2–3 套） | 出片 |
| 4 | 脚底硅胶垫槽位 | 防滑 |
| 5 | 背部 + 头部扩展接口开孔 | 扩展件 |
| 6 | 底部运动模块接口 | 模块化 |
| 7 | **预留摄像头开孔**（不装，只留位） | 为将来留余地 |

### 5.3 能力要求与验证

只需要 **L2：会用 Tinkercad 改现成模型**（学 2–3 小时）。

正式建模前先做**换壳测试**：同一台样机硬件，打 3 套极简外壳（狗 / 鸭 / 企鹅），各拍 15 秒视频同天发布，看完播率决定产品角色。

> sesame 已内置**磁吸模块化顶盖**（三种顶盖 + 磁吸帽子），换壳测试可直接改它的顶盖。

## 10. 与旧文档的差异

| # | 旧结论 | 新结论 |
|---|---|---|
| 1 | 有网页端（控制台内嵌 ESP32） | **取消网页端**，上位机为软件主线 |

| 6 | 软件任务以网页为主 | 软件任务以 **WPF 上位机**为主 |
