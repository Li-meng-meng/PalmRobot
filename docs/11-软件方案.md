## 1. 定位

**上位机是"大脑"**：负责所有需要算力的工作，通过小文本指令驱动机器人。

| 上位机负责 | 机器人负责 |
|---|---|
| 处理视频（视频 → 动作精华） | 播放动作 |
| 处理图片（表情 / 手势） | 渲染表情 |
| 基本设置（参数配置） | 接收配置 |
| 仿真 | — |
| 生产工具（标定 / 烧录 / 测试） | 被操作 |
| 通信（WiFi / 蓝牙 / 串口） | 应答 |

## 3. 电脑端上位机（WPF）

### 3.1 解决方案结构

| 路径 | 内容 |
|---|---|
| `PalmRobot.Core/` | **关键**：与界面无关的领域逻辑 |
| `PalmRobot.Core/Protocol/` | 串口文本 + WiFi JSON + BLE 指令编解码 |
| `PalmRobot.Core/Models/` | `.motion` 数据模型 |
| `PalmRobot.Core/Calibration/` | 标定算法 |
| `PalmRobot.Core/Validation/` | 动作包校验 |
| `PalmRobot.App/` | WPF 主程序（MVVM：Views / ViewModels / Services） |
| `PalmRobot.Cli/` | 可选命令行工具（复用 Core） |
| `tests/PalmRobot.Core.Tests/` | 单元测试 |

> **`PalmRobot.Core` 是整个方案的关键。** 协议、数据模型、标定算法都放这里；未来 MAUI App 直接引用，不用重写。

### 3.2 技术栈

| 用途 | 库 |
|---|---|
| UI | WPF（.NET 8） |
| MVVM | CommunityToolkit.Mvvm |
| 串口 | System.IO.Ports |
| 局域网 | Makaretu.Dns（mDNS）+ ClientWebSocket |
| 蓝牙 | Windows.Devices.Bluetooth 或 InTheHand.BluetoothLE |
| 3D 预览 | WebView2（内嵌本地页面，跑 three.js） |
| 图表 | LiveCharts2 或 OxyPlot |
| 日志 | Serilog |
| 配置 | System.Text.Json |
| 打包 | 单文件发布 + Inno Setup |

### 3.3 主界面布局

```
┌──────────────────────────────────────────────────────┐
│ 菜单：[设备] [动作] [视频] [图片] [设置] [固件] [工具] │
├───────────┬──────────────────────────────────────────┤
│ 设备列表   │  主工作区（标签页）                       │
│  ● COM3   │  ┌─调试─┬─标定─┬─动作─┬─视频─┬─日志─┐  │
│  ● 局域网  │  │        当前功能界面                 │  │
│  ○ 未连接  │  └────────────────────────────────────┘  │
│  [扫描]    │                                          │
```

## 5. 仿真

### 5.1 两套工具，各管一段

| 工具 | 语言 | 回答什么问题 | 用在哪 |
|---|---|---|---|
| **MuJoCo** | Python | **"这样走会不会摔？"**（重力、接触、力矩） | 开发期：步态设计、参数调优 |
| three.js | JS | "动作看起来对不对？" | 上位机内嵌的 3D 预览组件 |

> **MuJoCo 能"算命"，three.js 不能。** 四足最大的风险是"角度序列看着对，实际会摔"，MuJoCo 能在烧硬件前发现它。
> 两者不冲突：MuJoCo 用来**设计**步态，three.js 用来**展示**结果，输入同一份 8 通道角度序列。

### 5.2 模型是现成的，不要自己建

| 资产 | 来源 | 用途 |
|---|---|---|
| **MJCF** | `lukehollis/sesame-ml` → `assets/mjcf/sesame.xml` | 直接给 MuJoCo |
| **URDF** | 同上 → `assets/urdf/sesame.urdf` | three.js / ROS 通用 |
| 标定数据 | 同上 → `assets/calibration/default.yaml` | 关节零位 |
| 完整 CAD | `dorianborian/sesame-robot` → `hardware/cad/*.step` | 改结构时用 |

> MJCF 是 CAD 派生的，自带质量、惯量、执行器限位、接触几何——**仿真结果有物理意义**。
> **P0 的 3D 建模工作量 = 0。**

### 5.3 唯一要改的

改了外壳后质量分布会变，**用实物称重回填 MJCF 的质量 / 惯量参数**（改数字，不是建模）。

## 6. 视频处理（核心 AI 能力）

### 6.1 核心原则：提取精华，再表达

> 8 个自由度不可能复刻人体动作。做法是**从视频里提取"动作精华"，再用机器人的身体重新表达**。
> **能做的就做，做不了的就摇摆。**

### 6.2 七类精华特征

| 维度 | 从视频怎么提 | 机器人怎么表达 |
|---|---|---|
| 节拍 / 速度 | 音频能量包络 + onset → BPM | 播放速率、摇摆频率 |
| 能量 / 强度 | 肢体运动速度 × 幅度 | 摇摆幅度档位 |
| 方向 | 重心偏移、躯干朝向 | 行进、转向 |
| 周期性 | 动作片段自相关 | 循环 vs 单次 |
| 高度变化 | 髋 / 肩纵轴轨迹 | 站起 / 趴下 / 俯仰 |
| 情绪倾向 | 面部表情 + 动作柔和度 | 表情切换 + 动作刚柔 |
| 段落结构 | 音乐与动作切分 | 段落切换 |

### 6.3 映射表（翻译词典，核心资产）

| 视频里的动作 | 提取到的精华 | 机器人的表达 |
|---|---|---|
| 快速左右摇摆 | 高频 + 高能量 + 重心交替 | 原地左右摇摆，前腿大幅摆 |
| 缓慢挥手 | 单侧上肢周期运动 + 低频 | 单只前腿反复抬起 |
| 转圈 | 朝向持续单向变化 | 原地转向 + 身体倾斜 |
| 跳 | 垂直位移脉冲 | 前腿抬起 + 快速下蹲再起 |
| 蹲下 | 高度持续下降 | 趴下 + 低头 |
| 摊手 / 比心 | 单次大幅上肢 + 停顿 | 抬头 + 开心表情 + 单腿抬起 |
| 正常走路 | 周期性 + 前进方向 | 直接行走 |
| 街舞连拍 | 高频 + 多方向 + 高能量 | 高频摇摆 + 快速转向 |
| 倒地 | 高度骤降至最低 | 装死 |
| 完全识别不出 | 只剩节拍与能量 | 纯摇摆 + 表情随音乐 |

### 6.4 兜底原则：任何输入都必须有输出

1. 能映射成真实动作的优先走真实动作
2. 映射不了的一律落到"摇摆 + 表情"
3. **绝不失败** —— 不允许出现"分析失败，无法生成"
4. 降级也要降得好看（幅度包络 + 表情配合 + 收尾）

### 6.5 三级实现路径

| 级别 | 方案 | 工作量 |
|---|---|---|
| **L1 律动级** | 音频节拍 + 能量 → 驱动动作库 | 小（1–2 周） |
| **L2 精华级** | MediaPipe Pose → 7 类精华 → 查映射表 | 中（1–2 月） |
| L3 风格级 | 3D 动作 → 风格向量 → 参数化步态 | 大（3 月+） |

**落地顺序 L1 → L2 → L3。L1 就能撑起完整玩法。**

### 6.6 两段实现，各用最合适的语言

| 阶段 | 工具 | 用途 |
|---|---|---|
| **算法原型** | Python + MediaPipe + OpenCV + NumPy | 快速试参数、批量跑测试视频 |
| **落地实现** | 上位机内嵌（WebView + MediaPipe Web） | 用户可用 |

> **关键工程约定：映射表存成一份 JSON，Python 与 JS 读同一份。**
> 映射表是产品核心资产、一定会反复改；两边各写一份必然漂移。

## 7. 图片处理（表情与手势）

### 7.1 表情识别流程

**上位机摄像头 → MediaPipe Face Landmarker（468 关键点 + 52 blendshape）→ 52 维降为 12 维 → 低通滤波 + 速率限制 → 指令发送（10–20 fps）**

**不需要 Kalidokit** —— MediaPipe 原生就给 blendshape。

| 机器人参数 | 来源 blendshape |
|---|---|
| eyeOpen | eyeBlinkLeft / Right 反相 |
| squint | eyeSquintLeft / Right |
| browHeight | browInnerUp、browOuterUp |
| browAngle | browDownLeft / Right |
| mouthOpen | jawOpen |
| mouthCurve | mouthSmile 减 mouthFrown |
| pupilSize | 由 eyeWide 加权推导 |
| gazeX / gazeY | 眼球相对眼眶中心估算 |

### 7.2 三个必须做对的地方

| 要点 | 原因 |
|---|---|
| **低通滤波 + 变化速率限制** | 原始系数抖动大，直接推会让 OLED 抖成噪点 |
| **夸张化映射** | 单色小屏表达力有限，幅度要放大 |
| 端到端 < 150 ms | 超过 200 ms 用户就觉得不同步 |

### 7.3 手势识别

MediaPipe Hands → 手势 → 动作。约 3 天（V3 起）。

## 8. 通信协议

### 8.1 三条通道，一套指令

| 通道 | 用在 | 格式 |
|---|---|---|
| 串口（USB） | 烧录、标定、配网、底层调试 | 文本命令（便于人工敲） |
| WiFi（TCP / WebSocket） | 日常控制、动作下发、状态回传 | 文本命令或小 JSON |
| 蓝牙（BLE） | App 配网、近距离控制 | 文本命令 |

### 8.2 指令集（第 1 周冻结）

| 分类 | 指令 | 说明 |
|---|---|---|
| 控制 | `MOVE <v> <w>` | 速度 v(-100..100)，转向 w(-100..100) |
| 控制 | `STOP` | 停止 |
| 控制 | `POSE <name>` | stand / sit / wave / dance / sleep |
| 控制 | `PLAY <motion_id>` | 播放已存动作 |
| 控制 | `FRAME <t> <ch0..ch7>` | 写入关键帧（动作编辑用） |
| 表情 | `FACE <12 参数>` 或 `FACE <preset>` | 设置表情 |
| 状态 | `STATUS` | 返回 JSON |
| 状态 | `PING` | 心跳 |
| 配置 | `CFG GET` / `CFG SET <k> <v>` | 参数读写 |
| 维护 | `CAL <ch> <angle>` | 标定单舵机中位角 |
| 维护 | `WIFI <ssid> <pwd>` | 配网 |
| 维护 | `SAVE` / `REBOOT` / `RESET` | 保存 / 重启 / 恢复出厂 |

**返回格式**

| 返回 | 说明 |
|---|---|
| `OK` | 成功 |
| `ERR <code> <msg>` | 失败 |
| `{"v":12.4,"t":45,"batt":80,"pose":"stand","err":0}` | 状态 JSON |

> **机器人只接收这类小文本**（几十字节到几 KB），永不接收视频或图片。

### 8.3 动作文件 `.motion`

| 字段 | 说明 |
|---|---|
| `name` | 动作名 |
| `version` | 格式版本 |
| `duration_ms` | 总时长（毫秒） |
| `loop` | 是否循环 |
| `tracks.servo[]` | 关键帧：`{ t, ch:[8 个角度] }` |
| `tracks.face[]` | 关键帧：`{ t, expr:{12 维参数} }` |
| `tracks.audio[]` | 音效触发点：`{ t, clip }` |
| `meta` | 作者、来源（video_import 等）、标签 |

**要求**：时间轴毫秒；角度为绝对值 0–180；固件做插值与限速；文件可独立分享（2–10 KB）。
