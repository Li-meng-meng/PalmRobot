# 第一部分 · 软件工程师

## 1. 语言分工（先定这个，后面所有选型都跟着走）

| 语言 | 用在哪 | 性质 |
|---|---|---|
| **C++** | ESP32 固件 | 必需，但主要是嵌入式同学的活 |
| **Python** | 算法原型、物理仿真、音频分析、量产脚本、标定工具 | **开发期主力** |
| **JavaScript / HTML** | 用户侧 App（手机浏览器）、3D 预览、动作编辑器 | **产品期主力** |
| **C#** | 可选：装配工位的离线标定/调试小工具 | 低优先级 |

> **结论：Python 管"把东西做对"，JS 管"把东西交到用户手上"。**
> C# 在这个项目里用处最小 —— 除非你想给装配工位做个 Windows 端标定工具。

## 2. 关键认知：两套仿真工具，各管一段

这是本方案最重要的判断：

| 工具 | 语言 | 回答什么问题 | 用在哪 |
|---|---|---|---|
| **MuJoCo** | Python | **"这样走会不会摔？"**（重力、接触、力矩） | 开发期：步态设计、参数调优、风险评估 |
| **three.js** | JS | "动作看起来对不对？"（纯运动学） | 产品期：用户侧网页预览、动作编辑器 |

**为什么两个都要，而不是二选一：**

1. **MuJoCo 能"算命"，three.js 不能。** 四足最大的风险是"角度序列看着对，实际上会摔"。MuJoCo 有真实的重力与接触，**能在烧硬件之前就发现这个问题**。
2. **但 MuJoCo 进不了手机浏览器。** 用户要预览自己编排的动作，必须用轻量的 three.js。
3. **两者不冲突**：MuJoCo 用来**设计**步态，three.js 用来**展示**结果，输入的是同一份 8 通道角度序列。

## 3. 分任务选型（全部现成）

### 3.1 步态设计（开发期，Python + MuJoCo）

| 方案 | 说明 |
|---|---|
| **MuJoCo（Python）** | ✅ **首选**。能直接跑步态、看会不会倒 |
| 现成参考 | sesame 的步态代码、miniKame 的振荡器步态（可直接抄思路） |

**模型不用自己建 —— 现成的已经有了：**

| 资产 | 位置 | 用途 |
|---|---|---|
| **MJCF 模型** | `lukehollis/sesame-ml` → `assets/mjcf/sesame.xml`（12.5 KB） | **直接给 MuJoCo 用** |
| **URDF 模型** | `lukehollis/sesame-ml` → `assets/urdf/sesame.urdf`（16 KB） | 通用机器人描述，three.js / Unity / ROS 都能用 |
| 标定数据 | `lukehollis/sesame-ml` → `assets/calibration/default.yaml` | 关节零位等参数 |
| 完整 CAD | `dorianborian/sesame-robot` → `hardware/cad/Sesame-ESP32-v122.step`（30 MB） | 需要改结构时用 |
| 全套 STL | `dorianborian/sesame-robot` → `hardware/printing/stl/` | 3D 打印 |

> **这份 MJCF 是 CAD 派生的，自带质量、惯量、执行器限位和接触几何** —— 也就是说，MuJoCo 里跑出来的结果是有物理意义的，不是玩具。
>
> **P0 的 3D 建模工作量 = 0。** 你只需要下载、加载、跑起来。

**唯一需要改的**：等你们改了外壳，质量分布会变，MJCF 里的质量/惯量参数要回填（这是改数字，不是建模）。做法是**把实物称重，按部件更新参数**。

工作量：环境搭建 1–2 天，加载与验证 1 天，**调参 1–2 周**（这部分怎么都省不掉）。

### 3.2 用户侧 3D 预览（产品期，JS + three.js）

用 `STLLoader` 加载 sesame 的 STL，写一个简单的**腿部正运动学**（每条腿 2 舵机 → 2 段连杆，本质是三角函数），把 8 个角度实时套到模型上。约 3–5 天。

> 参考：GitHub 搜 "three.js quadruped" 有现成演示可借鉴。

### 3.3 视频动作提取（两段做，各用最合适的语言）

| 阶段 | 工具 | 用途 |
|---|---|---|
| **算法原型** | **Python + MediaPipe + OpenCV + NumPy** | 快速试参数、批量跑测试视频、打磨映射表 |
| **落地实现** | **MediaPipe Web + JS** | 用户手机浏览器里跑，零安装 |

**为什么这样分**：核心难点不在调用 MediaPipe（它是现成的），而在**7 类精华特征的提取逻辑和那张映射表**。这部分用 Python 迭代快得多（NumPy 处理时序很顺），调好之后翻译成 JS 只有几百行。

**保持两边一致的关键做法**：把**映射表单独存成一份 JSON**，Python 和 JS 都读它。

> 这是本方案最实用的工程建议：映射表一定会反复改（它是产品核心资产），如果两边各写一份，必然漂移。存成 JSON 数据，两边读同一份文件。

### 3.4 表情识别（同样两段）

| 环节 | 现成方案 |
|---|---|
| 人脸关键点 + 表情 | **MediaPipe Face Landmarker**（Python 版调试 / Web 版落地） |
| 输出 | **原生 52 个 blendshape 系数** |
| 转换 | **不需要 Kalidokit** —— 我们只要 blendshape，MediaPipe 原生就给 |

### 3.5 音乐律动

| 场景 | 方案 |
|---|---|
| 开发期调参、离线音频分析 | **librosa（Python）** —— beat tracking 成熟稳定，省大量时间 |
| 用户侧实时打拍 | **Web Audio API** `AnalyserNode` + 简单 onset 检测 |

> librosa 是 Python 音乐分析的事实标准，**这是"会 Python"带来的最大红利之一**。浏览器里没有对应能力的库，所以离线分析走 Python，实时走 Web。

### 3.6 网页控制台与动作编辑器

| 方案 | 说明 | 建议 |
|---|---|---|
| **ESP32 自带 Web Server** | 固件里放 HTML，连上 WiFi 打开 `192.168.4.1` 就能控制 | ✅ 首选，零依赖 |
| **表格式动作编辑器** | HTML 表格编辑关键帧（时间 + 8 角度 + 表情） | 先做这个 |
| 3D 可视化编辑器 | 复用 3.2 的 three.js 场景，角度滑块与预览联动 | 进阶再做 |

> MindPaw 就是用 ESP32 自己当热点 + 网页控制，用户打开 `192.168.4.1` 即可。

### 3.7 量产与运营脚本（Python 的隐藏红利）

这类活看起来小，但会反复用到，用 Python 写非常划算：

| 用途 | 说明 |
|---|---|
| 订单与排产表 | 从平台导出订单 → 自动生成采购清单与装配工单 |
| 标定数据批处理 | 收集每台机器人的舵机中位角，生成固件配置 |
| 测试报告 | 每台出厂测试数据自动归档 |
| 批量生成动作包 | 用脚本批量产出预设动作 |

> **别小看这些**：两人团队最大的瓶颈是重复劳动，这些脚本是"用一次省半天"的东西。

## 4. 工作量估计

| 模块 | 语言 | 估计 |
|---|---|---|
| MuJoCo 环境 + 模型改造 | Python | 3–5 天 |
| 步态设计与调参 | Python | **1–2 周** |
| three.js 用户侧预览 | JS | 3–5 天 |
| ESP32 网页控制台 | JS | 2–3 天 |
| 动作编辑器（表格版） | JS | 3–5 天 |
| 表情识别原型 | Python | 2–3 天 |
| 表情识别落地（→ 12 维） | JS | 3–5 天 |
| 视频动作提取 L1（节拍 + 能量） | JS | 5–8 天 |
| 视频动作提取 L2（精华级） | Python 原型 + JS 落地 | 3–4 周 |
| 量产/运营脚本 | Python | 按需，回报率高 |

## 5. 坑

| 坑 | 说明 | 对策 |
|---|---|---|
| **双语言逻辑漂移** | Python 原型和 JS 落地各写一份映射表，越改越不一致 | **映射表存成 JSON，两边读同一份** |
| **MuJoCo 与实物偏差** | 换了外壳后质量分布变化，仿真结果不准 | 用实物称重回填模型参数 |
| **浏览器安全限制** | 摄像头 API 必须 HTTPS 或 localhost | 本地打开或用局域网 HTTPS；不要用 `file://` |
| 手机兼容性 | iOS Safari 对 WebAssembly 支持较弱 | 优先安卓 Chrome；iOS 后期适配 |
| CORS | 网页直连 ESP32 会跨域 | 由 ESP32 自己托管网页（同源），问题消失 |
| three.js 版本 | API 变化快 | 锁定版本号 |
| blendshape 抖动 | 原始系数抖动大 | 低通滤波 + 变化速率限制（总纲 8.2.4） |

# 第二部分 · 嵌入式工程师

## 1. 一句话路线

> **全部用 Arduino 生态的现成库，自己不写的只有"步态调参"和"动作格式解析"。**

## 2. 分任务选型（全部现成库）

| 任务 | 现成方案 | 说明 |
|---|---|---|
| 开发框架 | **ESP32 Arduino Core** | 与 C++ 技能完全匹配 |
| 舵机驱动 | **Adafruit_PWMServoDriver** | PCA9685 官方库，一行 `setPWM()` 搞定 |
| 步态 | **二选一，都现成**：① sesame 的关键帧插值 ② miniKame 的振荡器步态 | ① 动作可编辑、易调；② 代码极短、天然平滑 |
| Web 服务 | **ESPAsyncWebServer** | 异步，不阻塞舵机控制 |
| WebSocket | **ArduinoWebSockets** 或 ESPAsyncWebServer 自带 | |
| 显示屏 | **Adafruit_SSD1306 + Adafruit_GFX** | 画圆/线/弧线够用 |
| 悬崖检测 | **VL53L0X 库**（ToF）或红外对管（读 ADC） | 红外对管最便宜（¥3） |
| JSON | **ArduinoJson** | 解析 .motion |
| 文件存储 | **LittleFS** | 存动作包 |
| OTA 升级 | **ArduinoOTA** | 网页上传固件 |
| 任务调度 | **FreeRTOS**（ESP32 自带） | 舵机与网络分核运行 |

## 3. 需要自己写的部分（工作量很小）

| 内容 | 工作量 |
|---|---|
| 引脚分配与初始化 | 半天 |
| 动作解释器（解析 .motion 并按时间驱动） | 2–3 天 |
| 舵机调度（限速、限流、限制同时动作数） | 1–2 天 |
| 表情渲染（12 维参数 → 128×64 帧） | 3–5 天 |
| 模块识别（扫 I2C 地址） | 半天 |
| 步态参数调优 | **最耗时，1–2 周** |

**真正花时间的是步态调参，不是写代码。**

## 4. 引脚分配建议（参考）

| 功能 | 引脚 | 说明 |
|---|---|---|
| I2C SDA / SCL | GPIO 8 / 9 | 接 PCA9685 + OLED + 扩展接口 |
| 电池电压检测 | ADC 引脚 | 分压电阻 |
| 悬崖检测 ×2（左/右） | ADC 或 GPIO | 红外对管 |
| 状态 LED | GPIO | |
| 串口调试 | UART0 | |

> 8 路舵机信号全部走 PCA9685，**不占用 MCU 的 PWM**，为扩展留出余量。

## 5. 坑

| 坑 | 说明 | 对策 |
|---|---|---|
| **舵机同时启动拉低电压** | 8 舵机同时动会瞬间掉压导致重启 | 电源并 1000 µF 电容；软件限制同时动作数（总纲 5.2） |
| 上电舵机乱转 | 上电瞬间 PWM 未初始化 | 初始化前先输出中位角 |
| SG90 买错版本 | 360° 版无法定位 | **必须买 180°** |
| 舵机批次差异 | 中位角偏差 5–10° | 固件提供**单舵机中位标定** |
| WiFi 与舵机抢 CPU | 网络阻塞导致动作卡顿 | FreeRTOS 分核；舵机刷新放高优先级任务 |

# 第三部分 · 外观设计

## 1. 一句话路线

> **不要从零建模** —— 直接复用 sesame 的 STL（Apache-2.0 允许），**只改外壳，不动腿部结构**。

## 2. 为什么只改外壳

| 改动范围 | 影响 |
|---|---|
| 只改头/身体外壳、屏幕窗口、配色 | **步态参数不用重调**，装配流程不变 |
| 改腿部结构 | 步态要重新调参（1–2 周工时） |

> 你们现在是 ¥300 启动、2 个工程师，**没有余量重新调步态**。第一版外观必须建立在不改结构的前提下。

## 3. 现成工具与资源

| 用途 | 现成方案 | 成本 |
|---|---|---|
| 基础模型 | **sesame 的 STL / CAD**（Apache-2.0） | ¥0 |
| **现成的多种顶盖** | `Top-Cover-Cat`（猫耳）/ `Top-Cover-No-Ears` / `Top-Cover-Enclosed` | ¥0 |
| **现成的磁吸帽子系统** | `magnetic-chainsaw-hat` / `magnetic-modular-mount-hat` | ¥0 |
| 建模（最简单） | **Tinkercad**（浏览器里用） | ¥0 |
| 建模（进阶） | Fusion 360 个人版 | ¥0 |
| 建模（自由造型） | Blender | ¥0 |
| 打印 | **嘉立创 3D 打印 / 淘宝代打** | ¥40–80/套 |
| 配色 | 双色 PLA 耗材 | 按克计 |
| 表情参考 | [stack-chan/m5stack-avatar](https://github.com/stack-chan/m5stack-avatar) 表情库 | ¥0 |

> **重要发现：sesame 已经内置了"磁吸模块化顶盖"系统。**
> 它提供三种顶盖（猫耳 / 无耳 / 封闭式），以及两种**磁吸帽子**（电锯帽、模块化安装座）。
> 这意味着两件事：
> 1. **"换壳测试"（8.6 之前提到的角色验证）可以直接用它的顶盖改，不用自己设计磁吸结构**
> 2. 我们规划的**扩展件接口（总纲 6.1）可以复用它的磁吸接口规范**，省掉一轮设计

## 4. 第一版最小改动清单

| 序号 | 改动 | 目的 |
|---|---|---|
| 1 | 头部外壳造型（含 OLED 窗口） | 定义角色（鸭子/企鹅/狗） |
| 2 | 身体外壳造型 | 同上 |
| 3 | 配色方案（2–3 套） | 出片更好看 |
| 4 | 脚底硅胶垫槽位 | 防滑（总纲 4.5 第 2 条） |
| 5 | 扩展接口开孔（背部/头部各 1） | 为扩展件预留 |
| 6 | 底部运动模块接口开孔 | 为模块化预留（总纲 4.7） |

**不要动**：腿部连杆、舵机安装位、舵盘连接方式。

## 5. 关键设计约束（来自总纲）

| 约束 | 出处 |
|---|---|
| 头部必须能放 0.96" OLED（约 27×27 mm 可视区） | 4.2 |
| 最长边 ≤ 150 mm | 3.3 |
| 整机 ≤ 450 g | 3.3 |
| 单个舵机 10 分钟内可换 | 4.1 |
| M2 螺丝统一规格 | 4.1 |
| 背部 + 头部各 1 个扩展位 | 6.1 |

## 6. 零成本验证角色（强烈建议）

正式建模之前先做**换壳测试**：

> 用同一台样机硬件，打 3 套极简外壳（狗 / 鸭 / 企鹅），各拍一条 15 秒视频，同一天发小红书和 B 站，看完播率与互动。

投入：代打 3 套约 ¥120–240（蹭到打印机则接近 ¥0）
产出：**用真实数据决定产品角色**，而不是猜。

## 7. 坑

| 坑 | 说明 |
|---|---|
| 直接改腿部结构 | 步态要重调，工时爆炸 |
| 屏幕窗口开太小 | 表情看不清，等于丢掉核心交互 |
| 忽略打印公差 | 舵机装不进去；**先打 1 套试装再批量** |
| 撞已知 IP 造型 | 避免酷似皮克斯/迪士尼角色 |
| 造型太复杂 | 支撑多、失败率高、代打贵 |

## 8. 3D 能力需求：到底要不要会画 3D

### 8.1 短答

> **需要，但分阶段。P0 完全不需要；P1 需要的是"会改现成模型"，不是"会从零建模"。**
> 项目里最难的那部分 3D 工作（腿部机构、舵机装配）**已经由 sesame 免费提供了**。
>
> **仿真的 3D 模型也不用画** —— sesame 生态里已经有现成的 **MJCF（MuJoCo 用）和 URDF（通用）**，见 3.1 的资产表。P0 的 3D 工作量是 0。

### 8.2 什么时候需要

| 阶段 | 需要吗 | 要做什么 | 能力等级 |
|---|---|---|---|
| **P0** 仿真 + 裸机 | ❌ **不需要** | 木板/纸板固定舵机，一个模型都不用画 | — |
| **P1** 创始团 | ✅ 需要（轻度） | 改 sesame 现成 STL：开 OLED 窗口、加扩展接口、外壳分件配色 | L2 |
| **P2** 小团滚动 | ✅ 需要（中度） | 角色化外壳（鸭/企鹅），尺寸改版 | L3 |
| **P3+** 成长期 | ✅ 需要（专业） | 系列化设计、模具准备 | L4 |

### 8.3 能力分层（这张表能省下招人的钱）

| 等级 | 能力 | 学习成本 | 本项目的价值 |
|---|---|---|---|
| L1 | 会下载 STL 直接打印 | 半天 | 够 P0 用 |
| **L2** | **会改现成模型**：开孔、加厚、缩放、拆件 | **Tinkercad，2–3 小时** | ✅ **P1 必需，性价比最高** |
| **L3** | **会参数化建模**：改尺寸自动更新 | **Fusion 360，1–2 周** | ✅ P2 需要 |
| L4 | 会有机曲面造型（角色造型） | Blender，1–2 月 | 可外包 |
| L5 | 会机构设计（连杆、舵机装配、公差链） | 专业级，1–2 年 | **❌ 本项目不做 —— 直接用 sesame 的** |

> **结论：你们实际需要的是 L2，最多到 L3。** 最难的 L5 靠复用 sesame 解决，这正是"不要从零设计"的价值所在。

### 8.4 建模软件选择

| 软件 | 难度 | 适合 | 建议 |
|---|---|---|---|
| **Tinkercad** | ★ | 浏览器里拖拽，改现成模型 | ✅ **P1 用这个** |
| **Fusion 360 个人版** | ★★★ | 参数化功能件，改尺寸自动更新 | ✅ **P2 主力**（个人版免费） |
| Blender | ★★★★★ | 有机曲面造型 | 外包时对方用 |

> 功能件（外壳、支架、开孔）优先用**参数化**工具（Fusion 360），因为你们一定会反复改尺寸（比如屏幕大了、舵机换了型号），参数化改一个数字就全更新。

### 8.5 谁来做

| 方案 | 成本 | 适合阶段 | 评价 |
|---|---|---|---|
| **工程师自己学 Tinkercad** | ¥0 + 2–3 天 | P1 | ✅ **第一期推荐** |
| 外包给外观设计 | ¥3,000+ | P1 之后做角色造型 | 已列入计划 |
| 淘宝 3D 建模代做 | ¥100–500/件 | 临时救急 | 可用 |
| 招专职建模 | 月薪 | — | ❌ **现在不需要** |

### 8.6 最省事的落地路径（推荐照这个顺序）

1. **先直接打印 sesame 原版 STL，一个字节都不改** → 验证装配与步态
2. 在 Tinkercad 里只做三个改动：**开 OLED 窗口、开扩展接口、把外壳拆成可换色的几件**
3. 到这里你已经有"自己的外观"了（虽然还是方块狗）
4. 等第一团交付、有预算了，再让外观设计做真正的角色造型

> **不要跳过第 1 步。** 用原版模型跑通装配，你才知道哪些地方必须改；直接上手改造型，会同时面对"装配不通"和"造型不对"两个问题。

### 8.7 一个必须有、但不需要会画的能力：**看懂模型能不能打**

| 检查项 | 标准 |
|---|---|
| 最小壁厚 | ≥ 1.2 mm（承力处 ≥ 2 mm） |
| 螺丝柱 | 外径加厚，孔留 0.2–0.3 mm 公差 |
| 悬垂角度 | > 45° 需要加支撑 |
| 打印方向 | 受力方向不要与层纹垂直 |
| 舵机安装位 | 留 0.2–0.3 mm 间隙，否则装不进去 |

> 这些可以让代打服务商提醒，但自己知道能省大量返工。**建议第一套打印前先打 1 个关键件试装，再打整套。**

### 8.8 一个诚实的提醒

**AI 文生 3D 目前不适合做这个。** 需要精确的舵机安装位、公差配合和承力结构，生成模型无法保证装配。它能做的是"概念图"，不能当功能件用。

# 第四部分 · 三个角色的协作接口

三人并行前，必须先冻结这三样，否则会互相返工：

| # | 要冻结的接口 | 谁定 | 谁依赖 |
|---|---|---|---|
| 1 | **动作文件格式 .motion**（8 通道 + 表情通道 + 时间轴） | 软件 + 嵌入式 | 外观（需知道动作幅度） |
| 2 | **引脚与接口定义**（I2C、扩展口、运动模块口） | 嵌入式 | 软件、外观 |
| 3 | **外壳与舵机的机械接口**（安装位、舵盘、螺丝） | 外观 | 嵌入式 |

> **建议**：这三份接口各写一页，冻结后再并行开发。这是三人团队最容易踩的坑 —— 各自做得飞快，最后拼不上。
