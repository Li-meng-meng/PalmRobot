> **状态：冻结。** 本规范是《10-总体规划》8.3 节"第 1 周冻结的四个接口"之一，由软件侧主导、嵌入式实现。

## 1. 总则

1. **三条通道，一套指令。** 串口、WiFi、蓝牙解析同一个指令表，语义与应答完全一致。
2. **小文本原则。** 单条指令 ≤ 256 字节；动作包上传（`PUTM`）除外，≤ 16 KB。**永不传输视频或图片。**
3. **应答必须。** 每条指令恰好一行应答；上传类指令（`PUTM`）为"声明行应答 + 数据流 + 终态应答"。
4. **失败不静默。** 任何解析失败、参数越界、执行失败都必须返回 `ERR`，不允许无应答（串口调试依赖此约定）。

## 2. 传输层约定

### 2.1 串口（UART0）

| 参数 | 值 |
|---|---|
| 波特率 | **115200**（嵌入式定稿前默认值，改则登记修订清单） |
| 数据位 / 校验 / 停止位 | 8 / None / 1 |
| 编码 | ASCII（`PUTM` 数据体为 UTF-8） |
| 行结尾 | `\n`；接收端忽略行尾 `\r` |
| 上电横幅 | 设备应输出一行 `READY <fw_version>`，便于上位机识别重连 |

### 2.2 WiFi（WebSocket）

| 参数 | 值 |
|---|---|
| 端口 | 80 |
| 路径 | `/ws` |
| 帧格式 | 文本帧，内容与串口行协议完全相同（含 `\n` 可省略） |
| mDNS 发现 | 服务名 `_palmrobot._tcp`，TXT 记录：`id=<设备ID>`、`fw=<固件版本>`、`model=<运动模块>` |

### 2.3 蓝牙（BLE，V3 起）

| 参数 | 值 |
|---|---|
| 服务 UUID | 软件侧在 V3 启动前与嵌入式共同登记（占位：`0000FF10-…`） |
| 写特征 | 收指令（文本，一次一包 ≤ 256 字节） |
| 通知特征 | 回应答 |

## 3. 行协议通用规则

```
请求：  CMD [arg1 arg2 ...]\n
应答：  OK\n            成功（无数据）
        OK <data>\n     成功（带数据）
        ERR <code> <msg>\n   失败
```

- 指令与参数用**单个空格**分隔；多余空格视为一个分隔符。
- 指令名**大小写不敏感**（`move` 等价 `MOVE`）；参数值大小写敏感（动作名、SSID 等）。
- 数值参数一律十进制，支持负号，不支持科学计数法与浮点（电压等由机器人上报时才出现小数）。
- 应答中的 `<msg>` 不含空格，用 `_` 代替（如 `ERR 1 BAD_RANGE`）。
- 未实现但已知的指令返回 `ERR 2 UNKNOWN_CMD`；未知的指令名同样如此，不区分。
- 机器人同时收到多条指令时**按序处理**，不并发执行动作指令；新的动作指令中断当前动作（详见 §5）。

## 4. 状态上报格式（冻结字段）

`STATUS` 指令与每秒一次的主动上报（WiFi 通道）使用同一 JSON：

```json
{"v":12.4,"t":45,"batt":80,"pose":"stand","err":0}
```

| 字段 | 类型 | 范围 | 说明 |
|---|---|---|---|
| `v` | float | 0–30 | 电池电压（V，保留 1 位小数） |
| `t` | int | -40–125 | 主控温度（°C） |
| `batt` | int | 0–100 | 电量百分比 |
| `pose` | string | `stand`/`sit`/`sleep`/`motion`/`safe` | 当前姿态；`safe` 表示保护态触发 |
| `err` | int | 见 §8 错误码 | 最近一次错误码，0 为正常 |

- **这 5 个字段冻结**；固件可追加字段（如 `rssi`、`uptime`），上位机忽略未知字段。
- JSON 单行、无空格、UTF-8，总长 ≤ 200 字节。
- 主动上报仅 WiFi 通道开启，周期 1 s，上位机可用 `CFG SET report 0` 关闭。

## 5. 指令表

### 5.1 运动控制

| 指令 | 参数 | 说明 | 应答 |
|---|---|---|---|
| `MOVE <v> <w>` | v=-100..100 线速度；w=-100..100 转向 | 持续运动，重复发送更新目标 | `OK` |
| `STOP` | — | 立即停止并回到站立缓冲 | `OK` |
| `POSE <name>` | name ∈ `stand`/`sit`/`wave`/`dance`/`sleep` | 切换预设姿态；`sleep` 同时熄屏 | `OK` |
| `PLAY <motion_id>` | 动作名或槽位号 0..9 | 播放已存动作包；`loop` 动作持续到 `STOP` | `OK` |

- 新的 `MOVE` / `PLAY` / `FRAME`（组播模式下）会**中断**当前动作并从新指令开始；中断不产生 `ERR`。
- `MOVE` 持续 3 s 未刷新且未收到其他运动指令，机器人自动回 `POSE stand`（防失联狂奔）。

### 5.2 动作编辑（上位机专用）

| 指令 | 参数 | 说明 | 应答 |
|---|---|---|---|
| `FRAME <t> <ch0> ... <ch7>` | t=0..600000 毫秒；ch=0..180 角度 | 单帧写入并立即执行（8 舵机一次到位） | `OK` |
| `FRAMES <n>` | 帧数 | 进入连续帧模式，随后 n 行 `FRAME`；收齐后统一执行（动作编辑器拖拽预览用） | `OK` 后每帧 `OK`，末帧 `OK DONE` |

- 通道映射（默认，**与仿真资产 `assets/calibration/default.yaml` 的 `joint_order` 一致**，嵌入式可用 `servo.map` 重映射）：

  | 通道 | 关节 | 部位 | 限位（°） |
  |---|---|---|---|
  | ch0 | R1 | 前右髋 | 45–180 |
  | ch1 | R2 | 后右髋 | 0–135 |
  | ch2 | L1 | 前左髋 | 0–135 |
  | ch3 | L2 | 后左髋 | 45–180 |
  | ch4 | R4 | 后右膝 | 0–180 |
  | ch5 | R3 | 前右膝 | 0–180 |
  | ch6 | L3 | 前左膝 | 0–180 |
  | ch7 | L4 | 后左膝 | 0–180 |

- 角度为**绝对值 0–180**，站立位见《21-动作文件格式规范》§5；插值与限速由固件完成（参考安全上限：600 °/s、单步 12°）。

### 5.3 表情

| 指令 | 参数 | 说明 | 应答 |
|---|---|---|---|
| `FACE <p1> ... <p12>` | 见 §6 十二维参数 | 设置实时表情（10–20 fps 由上位机节流） | `OK` |
| `FACE <preset>` | preset ∈ `happy`/`sad`/`angry`/`surprise`/`sleep`/`neutral` | 预设表情 | `OK` |

- 两种形式按参数个数区分：12 个数字 = 实时；1 个单词 = 预设。
- 发送速率超过 25 fps 时固件丢弃中间帧（丢弃不回 `ERR`）。

### 5.4 状态与心跳

| 指令 | 参数 | 说明 | 应答 |
|---|---|---|---|
| `STATUS` | — | 立即返回状态 JSON | `OK <json>` |
| `PING` | — | 心跳 | `PONG` |
| `VER` | — | 固件版本 | `OK <fw_version>` |

### 5.5 配置

| 指令 | 参数 | 说明 | 应答 |
|---|---|---|---|
| `CFG GET` | — | 返回全部配置 JSON | `OK <json>` |
| `CFG GET <k>` | 键名 | 返回单项 | `OK <v>` |
| `CFG SET <k> <v>` | 键 值 | 写入 RAM 并持久化到 LittleFS | `OK` |

**v1.0 配置键（冻结，只能增不能改语义）**

| 键 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `gait.stride` | 30 | 0–60 | 步长（°） |
| `gait.freq` | 2.0 | 0.5–5.0 | 步频（Hz） |
| `gait.lift` | 25 | 0–45 | 抬脚高度（°） |
| `face.bright` | 80 | 0–100 | 屏幕亮度 |
| `face.exagg` | 150 | 100–250 | 表情夸张化百分比 |
| `safe.batt_low` | 20 | 5–50 | 低电保护阈值（%） |
| `safe.cliff` | 1 | 0/1 | 悬崖检测开关 |
| `safe.stall_ms` | 500 | 100–2000 | 堵转判定时长（ms） |
| `servo.map` | `0,1,2,3,4,5,6,7` | 8 个数字 | 物理通道 → 逻辑通道重映射 |
| `report` | 1 | 0/1 | WiFi 状态主动上报开关 |

### 5.6 维护与标定

| 指令 | 参数 | 说明 | 应答 |
|---|---|---|---|
| `CAL <ch> <angle>` | ch=0..7；angle=0..180 | 单舵机中位标定写入 RAM | `OK` |
| `CAL SAVE` | — | 全部标定写入 LittleFS（掉电不丢） | `OK` |
| `CAL GET` | — | 返回 8 通道中位角 JSON | `OK {"mid":[90,...]}` |
| `WIFI <ssid> <pwd>` | SSID ≤ 32 字节；密码 ≤ 64 字节 | 配网并保存；连接失败自动回退等待配网 | `OK` 后异步 `EVT WIFI <ip>\|FAIL` |
| `SAVE` | — | 保存所有 RAM 配置 | `OK` |
| `REBOOT` | — | 软重启 | `OK` 后断开 |
| `RESET` | — | 恢复出厂（清配置、标定、动作包） | `OK` 后自动 `REBOOT` |

### 5.7 动作包管理

| 指令 | 参数 | 说明 | 应答 |
|---|---|---|---|
| `PUTM <name> <size>` | name ≤ 32 字符；size=数据字节数 | 声明上传；应答 `OK` 后**紧跟 size 字节 UTF-8 JSON**（`.motion` 内容，见配套规范）；校验通过写入 LittleFS | `OK PUT_READY` → 数据 → `OK SAVED` / `ERR` |
| `LISTM` | — | 列出已存动作包 | `OK <name> <size_bytes>\n...OK DONE` |
| `DELM <name>` | 动作名 | 删除动作包 | `OK` |

- 上传数据超出声明的 `size` → 连接层截断并 `ERR 9 OVERSIZE`。
- 上传超时（串口 5 s / WiFi 10 s 未收完）→ 放弃并 `ERR 10 TIMEOUT`。
- 动作包内容合法性由固件按配套规范校验（至少校验 version、duration_ms、角度范围）。

## 6. FACE 十二维参数（v1.0 冻结）

顺序固定，整数；除注明外范围 0–100（50 为中性）。

| # | 参数 | 范围 | 语义 | MediaPipe 来源 |
|---|---|---|---|---|
| 1 | eyeOpen | 0–100 | 睁眼程度，0 闭合 | eyeBlink L/R 反相 |
| 2 | squint | 0–100 | 眯眼 | eyeSquint L/R |
| 3 | browHeight | 0–100 | 眉毛高度 | browInnerUp、browOuterUp |
| 4 | browAngle | 0–100 | 眉毛内压（生气）/外挑（担心），50 中性 | browDown L/R |
| 5 | mouthOpen | 0–100 | 张嘴 | jawOpen |
| 6 | mouthCurve | 0–100 | 嘴角弧度，0 哭 100 笑 | mouthSmile − mouthFrown |
| 7 | mouthWide | 0–100 | 嘴宽 | mouthStretch |
| 8 | pupilSize | 0–100 | 瞳孔大小 | eyeWide 加权 |
| 9 | gazeX | -100–100 | 视线水平偏移 | 眼球相对眼眶估算 |
| 10 | gazeY | -100–100 | 视线垂直偏移 | 同上 |
| 11 | cheek | 0–100 | 脸颊抬起（笑肌） | cheekPuff、mouthPress |
| 12 | bright | 0–100 | 屏幕亮度 | —（非识别量，渲染层用） |

- 预设表情等价于一组固定 12 维值（映射表由固件内置，值见 `software/tools/motion_gen.py`）。
- 渲染含缓动，上位机无需发送中间过渡帧。

## 7. 事件上报（服务器主动推送）

| 事件 | 说明 |
|---|---|
| `EVT STATUS <json>` | 每秒状态上报（仅 WiFi，可关） |
| `EVT WIFI <ip>` / `EVT WIFI FAIL` | 配网结果 |
| `EVT SAFE <reason>` | 保护触发：`CLIFF` / `STALL` / `BATT_LOW` / `OVERHEAT`，触发即 `STOP` 并进 `safe` 姿态 |
| `EVT PLAY <name> DONE` | 动作播放完成（非循环） |

- 事件行仅在上行出现；上位机不得把 `EVT` 当作指令应答配对。

## 8. 错误码（冻结，只增不改）

| 码 | 名称 | 含义 |
|---|---|---|
| 0 | OK | 无错误 |
| 1 | BAD_ARGS | 参数个数或取值范围错误 |
| 2 | UNKNOWN_CMD | 未知指令 |
| 3 | BUSY | 通道/动作互斥冲突 |
| 4 | POWER_FAULT | 电源保护触发，拒绝运动指令 |
| 5 | BATT_LOW | 低电保护 |
| 6 | STALL | 堵转 |
| 7 | STORAGE_FULL | LittleFS 空间不足 |
| 8 | NOT_FOUND | 动作包 / 配置键不存在 |
| 9 | OVERSIZE | 上传数据超过声明大小 |
| 10 | TIMEOUT | 上传 / 执行超时 |
| 11 | CHECKSUM | 动作包 JSON 校验失败 |
| 12 | CAL_LOCK | 标定未保存时拒绝运动指令（先 `CAL SAVE` 或 `CAL CLEAR`） |

## 9. 上位机实现要求（对软件自己的约束）

1. 发送任何指令后**必须等应答再发下一条**（同一连接内严格请求-应答配对）；`PING` 超时 2 s 判定掉线。
2. `FACE` 由上位机节流到 ≤ 20 fps 并做低通滤波，不得依赖固件丢帧机制。
3. 必须处理 `EVT SAFE`：显示保护原因、禁用运动按钮直到 `pose` 脱离 `safe`。
4. `FRAME` 连续编辑用 `FRAMES` 批量模式，减少串口应答往返。
5. 所有收发原始行写入日志（Serilog），便于联调。
