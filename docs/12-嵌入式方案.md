# 嵌入式方案（机器人本体）

> 配套《10-总体规划》。机器人本体就是**产品本身**。
> 职责：基础硬件开发 + 本地实时控制 + **WiFi / 蓝牙 / 串口的指令服务**（只收发小文本）。

| 项目 | 内容 |
|---|---|
| 版本 | v1.0 |
| 日期 | 2026-09-16 |
| 适用 | 嵌入式工程师（ESP32 / Arduino / C++） |
| 工时口径 | 人天 |

---

## 1. 定位

机器人是**身体**：只做需要毫秒级实时反馈的事，只收发小文本，不做任何图像处理与 AI 推理。

| 机器人负责 | 不负责 |
|---|---|
| 舵机实时控制 | 视频处理 |
| 步态与动作播放 | 图片 / 表情识别 |
| 表情渲染 | 通用物体识别 |
| 安全保护（悬崖 / 堵转 / 低电） | 需要算力的任何事 |
| 接收指令、回传状态 | — |

### 2.2 三个必须记住的硬约束

| # | 约束 | 原因 |
|---|---|---|
| 1 | **舵机必须买 180° 版本** | 360° 版无法定位角度，整机不可用 |
| 2 | **电源轨并 1000 µF 电容 + 软件限流** | 8 舵机同时动作峰值 5.6–8 A，3 A 电源会被拉垮 |
| 3 | **固件必须提供单舵机中位标定** | SG90 批次差异 5–10° |

### 2.3 引脚分配（建议）

| 功能 | 引脚 | 说明 |
|---|---|---|
| I2C SDA / SCL | GPIO 8 / 9 | 接 PCA9685 + OLED + 扩展口 + 运动模块口 |
| 电池电压检测 | ADC | 分压电阻 |
| 悬崖检测 ×2（左 / 右） | ADC 或 GPIO | 红外对管（约 ¥3/只） |
| 状态 LED | GPIO | |
| 串口调试 | UART0 | 烧录与命令行调试 |

> **8 路舵机全部走 PCA9685，不占用 MCU 的 PWM**；PCA9685 还剩 8 路可给扩展舵机（尾巴 / 云台 / 夹爪）。

## 3. 模块化运动平台

### 3.1 架构

同一本体，换运动模块即可变形。

| 模块 | 执行器 | 模块成本 | 识别用 I2C 地址 |
|---|---|---|---|
| 四足（标配） | 8× SG90 180° | ≈ ¥60 | 0x40 |
| 轮式 | 2× SG90 360° | ≈ ¥27 | 0x41 |
| 履带 | 2× SG90 360° | ≈ ¥40 | 0x42 |
| 双足 | 4× SG90 + 尾撑 | ≈ ¥45 | 0x43 |
| 桌宠底座 | 无 | ≈ ¥5 | 0x44 |

### 3.2 三个关键技术选择

| 选择 | 理由 |
|---|---|
| **运动模块自带 PCA9685** | 本体只提供 4pin（5V/GND/SDA/SCL），与扩展口统一，只需一种连接器 |
| **用 I2C 地址区分模块** | 上电扫地址即知插了什么，自动加载对应驱动，零成本 |
| **轮式与履带用 360° 舵机** | SG90 360° 版与 180° 版同价（¥5.5），PWM 调速，**不需要电机驱动板、不需要编码器** |

### 3.3 双足模块的现实做法

纯双足平衡对 SG90 太难，改成**两腿 + 尾部小支撑轮**，定位为**展示形态**（能站、能摇、能挥手、能点头），**不承诺稳定行走**。

## 4. 固件架构

### 4.1 模块划分

| 模块 | 职责 |
|---|---|
| 动作解释器 | 解析 `.motion`，按时间轴驱动通道 |
| 舵机调度 | 限速、限流、限制同时动作数量（**保护电源**） |
| 表情渲染 | 12 维参数 → 128×64 帧，含缓动 |
| 姿态管理 | 站立 / 趴下等状态切换与安全过渡 |
| **指令服务** | WiFi / 串口 / 蓝牙接收小文本指令 |
| 状态回传 | 电压、温度、姿态、错误码 |
| 安全守护 | 悬崖检测、堵转超时、低电保护、看门狗 |
| 配置存储 | LittleFS 保存参数、动作包、WiFi 凭据 |

### 4.2 技术栈（全部现成库）

| 用途 | 库 |
|---|---|
| 框架 | ESP32 Arduino Core |
| 舵机 | Adafruit_PWMServoDriver |
| TCP / WebSocket 服务 | ESPAsyncWebServer（**仅做通信，不提供网页**） |
| 蓝牙 | ESP32 BLE 库（V3 配网用） |
| 显示 | Adafruit_SSD1306 + Adafruit_GFX |
| JSON | ArduinoJson |
| 文件系统 | LittleFS |
| OTA | ArduinoOTA |
| 调度 | FreeRTOS（ESP32 自带） |

### 4.3 任务与核分配（FreeRTOS）

| 任务 | 优先级 | 说明 |
|---|---|---|
| 舵机刷新 | 高 | 20 ms 周期，不能被网络阻塞 |
| 动作解释 | 高 | 按时间轴推进关键帧 |
| 表情渲染 | 中 | 10–20 fps |
| 网络收发 | 中 | 独立核 |
| 状态采集 | 低 | 每秒一次 |
| 看门狗 | 最高 | 异常复位 |

> **舵机刷新必须与网络分核**，否则 WiFi 一忙动作就卡顿。

## 5. 指令服务

### 5.1 三条通道

| 通道 | 用在 | 实现 |
|---|---|---|
| 串口（USB） | 烧录、标定、配网、底层调试 | UART0 + 文本命令解析 |
| WiFi（TCP / WebSocket） | 日常控制、动作下发、状态回传 | ESPAsyncWebServer |
| 蓝牙（BLE） | V3 App 配网与近距离控制 | ESP32 BLE |

**三条通道解析同一套指令**（指令集见《11-软件方案》8.2 节，由软件侧定义、你实现）。

### 5.2 数据量原则

| 收 | 发 |
|---|---|
| 指令（几十字节） | 状态 JSON（约 100 字节） |
| `.motion` 动作包（2–10 KB） | 错误码 |
| 配置参数 | |

**永不接收视频或图片。**

### 5.3 配网实现（无网页端）

| 阶段 | 方式 | 实现 |
|---|---|---|
| P0 | 编译时写死 | 代码里配置 SSID / 密码 |
| P1 | 串口配网 | 上位机发 `WIFI <ssid> <pwd>` → 存 LittleFS → 重启 |
| P2 | 保留串口配网 | |
| V3 | 蓝牙配网 | App 通过 BLE 发送凭据 |

**连接失败必须自动回退**：连不上时回到"等待配网"状态并提示，否则用户换路由器后设备永久卡死。

## 6. 明确不做（硬件硬约束）

| 不做 | 原因 |
|---|---|
| **机器人端视觉** | **ESP32-C3 没有摄像头接口（无 LCD_CAM），也不支持 PSRAM** |
| 通用物体识别 | ESP32 级别 MCU 不可能 |
| 本地 AI 推理 | 同上 |
| 网页服务 | 已决定取消网页端 |

> **若要加摄像头**，必须换 **ESP32-S3 + PSRAM**（+¥20–30）或加视觉协处理器（+¥30–45）。
> 摄像头唯一值得加的理由是玩法需要**低延迟**（追球、跟随人、实时避障）。**这是采购前必须定的事。**

## 9. 风险

| # | 风险 | 等级 | 对策 |
