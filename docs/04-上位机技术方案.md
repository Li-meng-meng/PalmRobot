## 1. 为什么必须有上位机（网页做不到的事）

| 需求 | 为什么网页不行 |
|---|---|
| **串口通信** | 浏览器访问串口能力受限，且需 HTTPS/localhost，产线环境不可靠 |
| **批量设备管理** | 网页一次只能连一台；产线要同时管多台 |
| **固件烧录** | 需要 esptool 级的串口操作，浏览器做不了 |
| **长时间稳定性** | 老化测试要跑几小时，浏览器标签容易被关或休眠 |
| **本地文件批处理** | 批量生成/校验动作包、批量生成配置 |
| **大屏动作编排** | 多轨时间轴在桌面端效率高得多 |
| **生产数据归档** | 每台的标定值、测试结果要落库留痕 |

> **一句话**：网页给用户，上位机给你们自己。用户的控制台是"零安装"，你们的生产力工具是"效率优先"。

## 2. 形态与技术栈

**WPF (.NET 8) + WebView2**：主体用原生 WPF，3D 预览用 WebView2 内嵌网页（**复用 `software/web/` 的 three.js 代码，不重写**）。

| 用途 | 用什么 | 说明 |
|---|---|---|
| UI 框架 | **WPF (.NET 8)** | |
| MVVM | **CommunityToolkit.Mvvm** | 官方库，轻量 |
| 串口 | `System.IO.Ports` | 标定、烧录 |
| 局域网 | mDNS（`Makaretu.Dns`）+ `ClientWebSocket` | 调试、测试、OTA |
| 3D 预览 | **WebView2** | 复用网页的 three.js |
| 图表 | LiveCharts2 或 OxyPlot | 温度/电流曲线 |
| 日志 | Serilog | 落盘留痕 |
| 配置 | `System.Text.Json` | |
| 打包 | 单文件发布 + Inno Setup | |

## 3. 功能模块（10 个，含工时）

| # | 模块 | 功能 | 优先级 | 工时 |
|---|---|---|---|---|
| 1 | **设备管理** | 串口/USB/mDNS 发现、连接、多设备列表、在线状态 | P0 | 3 天 |
| 2 | **调试面板** | 单舵机微调、实时角度回显、读回配置、快捷动作触发 | P0 | 4 天 |
| 3 | **出厂标定** ★ | 逐舵机中位标定 → 生成配置 → 写入设备 → 归档留痕 | **P0** | 5 天 |
| 4 | **动作编辑器** | 多轨时间轴、关键帧拖拽、实时预览 | P1 | 8 天 |
| 5 | 动作包管理 | 导入导出 `.motion`、批量生成、合法性校验 | P1 | 3 天 |
| 6 | 固件烧录 | 串口烧录、版本选择、批量烧录 | P1 | 4 天 |
| 7 | **批量测试 / 老化** | 多台并行跑 30 分钟，记录温度/电流/失败 | P1 | 5 天 |
| 8 | OTA 管理 | 局域网批量推送固件 | P2 | 3 天 |
| 9 | 仿真联动 | 调步态参数 → 同步到 MuJoCo 看效果 | P2 | 5 天 |
| 10 | 订单 / 工单 | 从订单生成采购清单与装配工单 | P1 | 3 天 |

**合计：P0 = 12 人天，P1 = 23 人天，P2 = 8 人天，共 43 人天。**

> **模块 3（出厂标定）是硬需求**：P1 交付创始团 5 台时，如果没有标定工具，每台要手工调 8 个舵机的中位角，装配时间会失控。

## 4. 主界面布局

```
┌──────────────────────────────────────────────────────────┐
│ 菜单：[设备] [动作] [固件] [工具] [帮助]                  │
├───────────┬──────────────────────────────────────────────┤
│ 设备列表   │  主工作区（标签页）                           │
│  ● COM3   │  ┌─调试──┬─标定──┬─动作──┬─测试──┬─日志─┐  │
│  ● COM5   │  │                                       │  │
│  ○ 未连接  │  │        当前功能界面                    │  │
│           │  │                                       │  │
│  [扫描]    │  └───────────────────────────────────────┘  │
├───────────┴──────────────────────────────────────────────┤
│ 状态栏：已连接 COM3 · 固件 v0.3.1 · 12.4 V · 45 °C       │
└──────────────────────────────────────────────────────────┘
```

**设计要点**

- 左侧设备列表常驻 —— 产线同时插多台是常态
- 主区用标签页切换功能，避免多窗口
- 状态栏常显电压与温度（这两个是硬件故障的第一信号）
- 所有操作都有日志（便于排障与售后追溯）

## 5. 与固件的通信

两条通道，**共用同一套命令表**（与网页端一致，避免各写一套）：

| 通道 | 用在 | 特点 |
|---|---|---|
| **串口（USB）** | 标定、烧录、底层调试 | 简单文本命令，便于人工调试 |
| **局域网 WebSocket** | 调试、测试、OTA | JSON 消息，与网页同协议 |

## 6. 关键设计：领域逻辑抽成 .NET 类库

```
PalmRobot.Core  ←  .motion 模型 / 通信协议 / 标定算法 / 校验逻辑
      ├── 被 WPF 上位机引用
      ├── 被未来的 MAUI App 引用      ← 未来上 App 时不用重写
      └── 也可以被 CLI 工具引用
```

> **这是为 MAUI 铺路的关键一步。** 把协议、数据模型、标定算法放在 .NET 类库里，未来做手机 App 时这部分直接复用，只重写界面层。

## 7. 与网页的分工边界

| 功能 | 网页（用户） | 上位机（内部） |
|---|---|---|
| 遥控、播放动作 | ✅ 主力 | ✅ 调试用 |
| 表情切换 | ✅ | ✅ |
| 动作编排 | **简化版（表格）** | **完整版（时间轴）** |
| 3D 预览 | ✅ | ✅（WebView2 复用同一份代码） |
| 出厂标定 | ❌ | ✅ **唯一入口** |
| 固件烧录 | ❌ | ✅ **唯一入口** |
| 批量测试 | ❌ | ✅ **唯一入口** |
| OTA 升级 | 简化版（单台） | ✅ 完整（批量） |
| 订单 / 工单 | ❌ | ✅ |

**原则：涉及批量、串口、长时间运行的，一律放上位机；用户日常操作，一律放网页。**

## 9. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| **与网页重复造轮子** | 两边都做动作编辑器 | 网页只做简化版；复杂编辑只在上位机 |
| **工时被低估** | 8 天做完整时间轴编辑器偏紧 | 先出表格版，时间轴延后 |
| WebView2 依赖 | Win10/11 一般自带，Win7 没有 | 安装包内嵌 WebView2 Runtime |
| WPF 只支持 Windows | 你们两人都用 Windows | 内部工具无影响 |
| 上位机功能膨胀 | 什么都想加，拖垮排期 | 严格按第 3 节的优先级，P2 的模块可砍 |
